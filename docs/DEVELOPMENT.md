# Разработка и проверки

## Подготовка

Нужен Bun версии из `package.json` или новее.

```sh
bun install --frozen-lockfile
bun run lint
bun run typecheck
bun test
```

Сетевые учётные данные и Ollama не требуются для тестов. Интеграционный тест
аудиопотока использует настоящий FFmpeg, если он установлен; иначе пропускается.
Остальные проверки процессов используют дочерние процессы Bun. Терминальные тесты
работают через псевдотерминал: проверяют навигацию клавишами и мышью, разделённые пакеты событий, закрепление позиции
при новых логах, ограничение истории, resize, буквальный поиск с подсветкой и
выход через `q` или Ctrl+C.

Некоторые песочницы блокируют запись в каналы дочерних процессов. Ошибки EPERM
при проверке потоков нужно проверять в среде, разрешающей subprocess I/O, а не
скрывать пропуском тестов. Живое подключение к Discord, Telegram, Ollama и реальное
извлечение музыки с провайдеров остаются отдельной интеграционной проверкой.

## Линтер

```sh
bun run lint
bun run lint:fix
```

Oxlint проверяет `index.ts`, все исходники `src/` и тесты `test/`. Конфигурация
`.oxlintrc.json` включает проверки корректности JavaScript/TypeScript и плагины
TypeScript, Unicorn и Oxc. `Bun` объявлен глобальным объектом. Зависимости,
локальная память и служебные каталоги исключены.

Любая ошибка или предупреждение завершает проверку с ненулевым кодом. `lint:fix`
применяет доступные безопасные исправления, после чего нужно проверить diff и
запустить форматирование. Prettier отвечает за стиль, а TypeScript — за проверку
типов; линтер дополняет обе проверки. Неиспользуемые локальные исключения правил
тоже проверяются. Намеренно неиспользуемые параметры и переменные обозначаются
префиксом `_`; исключение для фильтра управляющих символов терминала локально
и снабжено причиной.

## Форматирование

```sh
bun run format
bun run format:check
```

Prettier установлен локальной dev-зависимостью. Стиль задан `.prettierrc.json`.
Команда форматирует исходники, тесты, JSON-конфигурацию и Markdown. Исключения в
`.prettierignore`: зависимости, служебные каталоги, память, секреты, локальные
факты/личность и lockfile, который обновляет сам Bun.

При добавлении зависимостей коммитьте `bun.lock`. Для изменения форматирования
обновляйте общую конфигурацию, а не исключения для отдельных функций.

## Покрытие

| Тесты                                                             | Что проверяют                                                                                 |
| ----------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| `assistant`, `queue`, `context`, `models`, `text`                 | Сессии, отмена, приоритеты, ограничения контекста и конфигурация                              |
| `supervisor`, `spontaneous`                                       | Структурные решения, достоверность фактов и ограничения самостоятельных реплик                |
| `memory`, `paths`                                                 | Изоляция и сохранение фактов, новые каталоги и буквальные имена файлов                        |
| `history`, `images`, `image-search`, `gif-search`, `web-fallback` | Ограниченные платформенные возможности, загрузки и резервные провайдеры                       |
| `discord`, `telegram`, `telegram-format`                          | Маршрутизация сообщений, доставка, форматирование и разрешения                                |
| `music`                                                           | Импорт, сохранение, кнопки, формы, режимы и локальные снимки состояния                        |
| `music-queue`                                                     | Повтор, skip, перемешивание, дубликаты и исключение неудачных треков                          |
| `music-process`                                                   | Реальные процессы Bun, двоичные потоки, лимиты вывода, отмена и остановка                     |
| `shutdown`                                                        | Выход с открытым HTTP-сервером, остановкой дочернего процесса и зависшим отключением адаптера |
| `cli`, `tui`, `tui-scroll`, `tui-mouse`, `tui-search`             | Клавиши, размеры экрана, очистка терминала и завершение процесса                              |

Имена соответствуют файлам `test/<имя>.test.ts`. Общие частичные двойники находятся
в `test/fixtures.ts`; `test/temp.ts` создаёт изолированные каталоги и убирает их
после теста. Новые проверки должны проверять наблюдаемое поведение и границы
внешних API, а не дублировать строки реализации.

## Документирование изменений

Добавляйте описание модуля и JSDoc для его публичных функций и контрактов.
Описывайте назначение, ограничения, отмену и значимые побочные эффекты. Для сложных
внутренних переходов объясняйте инварианты. При изменении пользовательских команд
обновляйте [справочник](COMMANDS.md); при изменении архитектуры —
[описание модулей](ARCHITECTURE.md). Настройки запуска описаны в [README](../README.md).
