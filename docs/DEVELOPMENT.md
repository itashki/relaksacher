# Разработка и проверки

## Подготовка

Нужен Bun версии из `package.json` или новее. Для полного окружения на Linux
выполните `nix develop path:.` или `nix-shell` из корня проекта. Обе команды используют
закреплённый `flake.lock` и общий список пакетов в `nix/dev-shell.nix`.
Nix-файлы форматируются через `nix fmt`; остальные файлы — через Prettier.

```sh
bun install --frozen-lockfile
bun run lint
bun run typecheck
bun test
```

Сетевые учётные данные и Ollama не требуются для тестов. Интеграционный тест
аудиопотока использует настоящий FFmpeg, если он установлен; иначе пропускается.
Остальные проверки процессов используют дочерние процессы Bun. Терминальные тесты
работают через псевдотерминал: проверяют навигацию клавишами и мышью, разделённые пакеты событий, закрепление позиции
при новых логах, ограничение истории, resize, буквальный поиск с подсветкой и
выход через `q` или Ctrl+C.

Некоторые песочницы блокируют запись в каналы дочерних процессов. Ошибки EPERM
при проверке потоков нужно проверять в среде, разрешающей subprocess I/O, а не
скрывать пропуском тестов. Живое подключение к Discord, Telegram, Ollama и реальное
извлечение музыки с провайдеров остаются отдельной интеграционной проверкой.

## Структура проекта

```text
index.ts                       постоянный хост TUI, транспорта и мягкого рестарта
src/
  config.ts                    конфигурация окружения
  types.ts                     общие публичные контракты
  core/
    assistant/                 сессии модели, контекст, промпты и фоновые решения
    memory/                    постоянная память и история расшифровок
    music/                     очередь воспроизведения и локальный мониторинг
    speech/                    подготовка текста, транскрипция и Whisper
    tools/                     инструменты модели, поиск и погода
    *.ts                       общие очереди, серии сообщений, пути и shutdown
  adapters/
    discord/
      access/                  настройки доступа и приватное меню
      music/                   команды, кнопки и голосовой плеер Discord
      *.ts                     клиент, сообщения, потоковая доставка и TTS
    telegram/                  клиент, Bot API, форматирование и сообщения
    terminal/                  CLI, TUI, навигация, мышь и поиск
    music/                     музыкальные источники, метаданные и плейлисты
    speech/                    адаптер Silero и загрузка аудио
    shared/                    общая работа с изображениями
scripts/                       проверка размера файлов и Python CLI Silero
test/                         тесты по соответствующим подсистемам
```

`src/runtime/` содержит заменяемую сборку приложения, загрузчик и постоянные
соединения мессенджеров. Для проверки изменений логики без обрыва генерации
используйте `bun start`, затем кнопку `[R Рестарт]` или клавишу `R` в TUI.
`bun dev` использует `--watch` и перезапускает процесс с отменой текущей работы.

В `test/` используются группы `assistant/`, `discord/`, `telegram/`, `terminal/`,
`music/`, `speech/`, `tools/` и `core/`. Общие фабрики и временные каталоги находятся
в `test/support/`. Например, `bun test test/discord` запускает проверки Discord,
а `bun test test/music` — проверки музыкальной подсистемы.

Входные файлы подсистем называются `index.ts` и содержат реальные фабрики,
а не дополнительные цепочки реэкспортов. Discord-специфичные меню и состояния
хранятся в `adapters/discord/music/`; получение треков, метаданных и переносимые
плейлисты — в `adapters/music/`. Ядро не зависит от платформенных клиентов.
При переносах обновляйте также динамические импорты, `Bun.resolveSync`, пути
к ресурсам от `import.meta.url` и описание модулей в архитектуре.

## Размер модулей

Каждый TypeScript-файл в `src/`, `test/`, `scripts/` и `index.ts` ограничен
600 физическими строками, включая комментарии и пустые строки. Предпочтительный
размер самостоятельного модуля — 200–400 строк. Делите код по ответственности:
состояние, доставка, команды и интерактивные элементы; общие тестовые фабрики
держите отдельно от самих проверок. Сжатие форматирования не заменяет разделение.

`bun run check:size` проверяет размер и завершает работу с ошибкой при превышении.
Эта проверка автоматически выполняется перед линтером в `bun run lint` и
`bun run lint:fix`, включая новые, ещё не добавленные в Git файлы.

## Линтер

```sh
bun run lint
bun run lint:fix
```

Oxlint проверяет `index.ts`, все исходники `src/`, тесты `test/` и TypeScript-инструменты `scripts/`. Конфигурация
`.oxlintrc.json` включает проверки корректности JavaScript/TypeScript и плагины
TypeScript, Unicorn и Oxc. `Bun` объявлен глобальным объектом. Зависимости,
локальная память и служебные каталоги исключены.

Любая ошибка или предупреждение завершает проверку с ненулевым кодом. `lint:fix`
применяет доступные безопасные исправления, после чего нужно проверить diff и
запустить форматирование. Prettier отвечает за стиль, а TypeScript — за проверку
типов и неиспользуемых локальных переменных/параметров; линтер дополняет обе проверки. Неиспользуемые локальные исключения правил
тоже проверяются. Намеренно неиспользуемые параметры и переменные обозначаются
префиксом `_`; исключение для фильтра управляющих символов терминала локально
и снабжено причиной.

## Форматирование

```sh
bun run format
bun run format:check
```

Prettier установлен локальной dev-зависимостью. Стиль задан `.prettierrc.json`.
Команда форматирует исходники, тесты, JSON-конфигурацию и Markdown. Исключения в
`.prettierignore`: зависимости, служебные каталоги, память, секреты, локальные
факты/личность и lockfile, который обновляет сам Bun.

При добавлении зависимостей коммитьте `bun.lock`. Для изменения форматирования
обновляйте общую конфигурацию, а не исключения для отдельных функций.

## Покрытие

| Тесты                                                             | Что проверяют                                                                                 |
| ----------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| `assistant`, `queue`, `context`, `models`, `text`                 | Сессии, отмена, приоритеты, ограничения контекста и конфигурация                              |
| `supervisor`, `spontaneous`                                       | Структурные решения, достоверность фактов и ограничения самостоятельных реплик                |
| `memory`, `paths`                                                 | Изоляция и сохранение фактов, новые каталоги и буквальные имена файлов                        |
| `history`, `images`, `image-search`, `gif-search`, `web-fallback` | Ограниченные платформенные возможности, загрузки и резервные провайдеры                       |
| `discord`, `telegram`, `telegram-format`                          | Маршрутизация сообщений, доставка, форматирование и разрешения                                |
| `music`                                                           | Импорт, сохранение, кнопки, формы, режимы и локальные снимки состояния                        |
| `music-queue`                                                     | Повтор, skip, перемешивание, дубликаты и исключение неудачных треков                          |
| `music-process`                                                   | Реальные процессы Bun, двоичные потоки, лимиты вывода, отмена и остановка                     |
| `shutdown`                                                        | Выход с открытым HTTP-сервером, остановкой дочернего процесса и зависшим отключением адаптера |
| `cli`, `tui`, `tui-scroll`, `tui-mouse`, `tui-search`             | Клавиши, размеры экрана, очистка терминала и завершение процесса                              |

Имена соответствуют файлам `test/<имя>.test.ts`. Общие частичные двойники находятся
в `test/support/fixtures.ts`; `test/support/temp.ts` создаёт изолированные каталоги и убирает их
после теста. Новые проверки должны проверять наблюдаемое поведение и границы
внешних API, а не дублировать строки реализации.
