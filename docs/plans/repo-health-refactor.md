# Repo health refactor: split near-limit modules, share atomic writes, fix stale docs

Goal: Get the two modules at the 600-line limit back to a size that can be edited, by splitting them along existing responsibilities. Remove the atomic-JSON-write code that is copied in five modules. Fix development docs that still describe the removed hot-reload loader. Line numbers cited below refer to commit 06e4e26; after earlier steps, locate blocks by the named identifiers instead. Behavior must not change; every step keeps lint, typecheck, format and tests green.
Decisions:

- Baseline (verified 2026-11-19): `bun run lint`, `bun run typecheck` and `bun test` pass (397 tests). However, `src/adapters/telegram/index.ts` is exactly 600 lines and `src/core/assistant/index.ts` is 593, so any feature edit to either one fails `check:size`. Both are split by responsibility, not by compressing formatting. The target size is 200–400 lines for new modules and at most ~450 for the remaining `index.ts` files.
- `handleMessage` in Telegram `index.ts` is one function of about 390 lines that holds four separate jobs: voice/transcription commands, reply-chain and conversation building, streamed rendering, and session wiring. They are extracted in separate steps so each one can be checked against `test/telegram` on its own.
- Shared closure state in the Telegram adapter (`api`, `me`, `remember`, `histories`, `batches`, `active`, `config`) is passed through one explicit deps object. `me` is a reassigned `let`, set lazily in `handleUpdate`/`start()`, so extracted code must receive it per call or through a getter `getMe()`. It must never be captured at factory construction time.
- Atomic writes: one helper in `src/core/atomic-file.ts`. It keeps the existing `${file}.tmp` naming and `node:fs/promises.rename`, which AGENTS.md says to keep. No other behavior changes: no new race fixes, no `createPath` changes.
- No Node-to-Bun migration step. The remaining `node:` imports are either required by AGENTS.md (`rename`, the readline/raw-mode TUI, the `Readable` adapter for `@discordjs/voice`) or have no Bun-native equivalent (`appendFile` in request-log, which is already documented, plus `chmod`, `tmpdir`, `randomInt` and `path.resolve`).
- No dead-code step. The only exports referenced in a single file are public type contracts (`DashboardOptions`, `SearchSpan`, `WeatherRequest`, `TelegramRequest`, `MusicMessageRow`).
- Docs are updated inside each extraction step: an `@file` header on each new module, plus a Russian row in the matching `docs/ARCHITECTURE.md` table, with the rows for slimmed `index.ts` files adjusted.
- Restart, commit/push and CI verification are done by the dispatcher after the final step; they are not plan steps.
