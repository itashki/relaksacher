# Архитектура

Приложение работает на Bun. `index.ts` держит TUI, соединения мессенджеров и
процесс Whisper. `src/runtime/application.ts` создаёт заменяемую логику: Ollama-клиенты,
общую очередь генерации, хранилище памяти и обработчики адаптеров. Импорт модулей
сам по себе не запускает сетевые подключения.

## Конфигурация и контракты

| Модуль                 | Ответственность                                                                     |
| ---------------------- | ----------------------------------------------------------------------------------- |
| `src/config.ts`        | Проверка переменных окружения, чтение `facts.json5` и `personality.json5`           |
| `src/types.ts`         | Контракты сессий, платформенных возможностей, инструментов и локального мониторинга |
| `src/core/shutdown.ts` | Единое завершение приложения, ожидание отключения клиентов и предел времени выхода  |
| `src/core/paths.ts`    | Разрешение путей, включая ещё не существующие файлы и имена с URL-пунктуацией       |

Настройки читаются при старте. Факты и личность перечитываются также при мягком
рестарте; изменения `.env` требуют полного запуска процесса. Секреты и локальная
память не входят в форматирование исходников.

## Мягкий рестарт

| Модуль                         | Ответственность                                                                                   |
| ------------------------------ | ------------------------------------------------------------------------------------------------- |
| `src/runtime/application.ts`   | Создание и освобождение заменяемых обработчиков и клиентов модели                                 |
| `src/runtime/loader.ts`        | Новая сборка всех локальных зависимостей через `Bun.build`, проверка конфигурации до переключения |
| `src/runtime/transports.ts`    | Постоянный Discord gateway и Telegram runner; ответы на кнопки во время рестарта                  |
| `src/runtime/contracts.ts`     | События и соединения на границе постоянной и заменяемой частей                                    |
| `src/core/restart.ts`          | Буфер входящих событий, ожидание завершения принятых обработчиков и сериализация рестартов        |
| `src/core/assistant-bridge.ts` | Переподключение TUI к новому ассистенту без потери журнала и терминальных режимов                 |
| `src/core/project.ts`          | Корень проекта для конфигурации, памяти и Python-скрипта в исходниках и сборках                   |

Сборка использует отдельный идентификатор модуля и включает локальные зависимости,
чтобы изменения вложенных импортов не оставались в кеше. Пакеты остаются внешними:
Discord-классы и нативные библиотеки имеют ту же идентичность. Временный файл в
`node_modules/.cache/relaksacher` удаляется после импорта и проверки конфигурации.

Во время сборки старый обработчик продолжает принимать события. Затем новые
сообщения буферизуются, а принятые обработчики завершаются вместе с debounce,
очередью модели, инструментами и последней отправкой ответа. Отмена остаётся
доступна через прежний обработчик. После ожидания заменяются обработчики и
ассистент, буфер запускается в порядке поступления. Сетевые подключения не
пересоздаются. Ошибка подготовки не отключает работающую версию.

Буфер находится в памяти и предназначен для планового мягкого рестарта, а не
восстановления после аварии. Музыкальный плеер и временные меню/кеши адаптеров
пересоздаются; сохранённые плейлисты и память читаются с диска. Постоянные части
хоста, пакеты и настройки окружения обновляются полным запуском процесса.

## Диалоги и инструменты

1. Адаптер распознаёт обращение и собирает явную цепочку ответов.
2. `assistant.createSession()` создаёт одноразовую сессию с методами `run()` и `stop()`.
3. `core/queue.ts` последовательно выполняет запросы; фоновые решения имеют меньший приоритет.
4. `core/assistant/supervisor.ts` выбирает режим обдумывания. `core/assistant/prompt.ts` собирает инструкции и контекст.
5. `core/assistant/context.ts` оценивает размер входа, удаляя необязательную историю раньше текущего запроса.
6. `core/assistant/index.ts` читает поток модели и исполняет ограниченное число раундов инструментов.
7. Адаптер получает накопленный текст через ожидаемый `onUpdate()` и отправляет его в чат.

Отмена охватывает ожидание очереди и текущую генерацию. Некоторые уже запущенные
операции инструментов могут завершиться позже. Локальные рассуждения попадают в
операторский мониторинг и журнал; сообщения чата их не содержат.

| Модуль                          | Ответственность                                                                           |
| ------------------------------- | ----------------------------------------------------------------------------------------- |
| `core/tools/index.ts`           | Доступные модели инструменты и проверка их аргументов                                     |
| `core/tools/weather.ts`         | Геокодирование и почасовой прогноз Open-Meteo с проверкой периода и неоднозначных локаций |
| `core/memory/index.ts`          | Раздельная память групп, последовательные изменения, атомарная замена файлов              |
| `core/tools/web-fallback.ts`    | Ограниченные HTTP-загрузки, проверка публичных адресов и резервный веб-поиск              |
| `core/tools/image-search.ts`    | Поиск и проверка кандидатов изображений                                                   |
| `core/tools/gif-search.ts`      | Необязательный поиск GIF через KLIPY                                                      |
| `core/assistant/spontaneous.ts` | Вероятностный отбор редких самостоятельных реплик с интервалами ожидания                  |
| `core/text.ts`                  | Разбор `/think` и общие текстовые операции                                                |

История читается отдельным инструментом через возможность, переданную адаптером.
Произвольные ссылки модели не превращаются в исходящие изображения: отправлять
можно только выбранные кандидаты текущей сессии.

## Адаптеры

| Модуль                        | Ответственность                                                                            |
| ----------------------------- | ------------------------------------------------------------------------------------------ |
| `adapters/discord/index.ts`   | Discord-события, ветки, цепочки ответов, сообщения и кнопки остановки                      |
| `adapters/telegram/index.ts`  | Telegram polling, ограниченный кэш цепочек ответов и потоковая доставка                    |
| `adapters/telegram/api.ts`    | grammY, тайм-ауты, ограниченные повторы безопасных запросов                                |
| `adapters/telegram/format.ts` | Markdown → Telegram HTML с корректными границами длинных сообщений                         |
| `adapters/shared/images.ts`   | Загрузка изображений с платформенных хостов и подготовка входов модели                     |
| `adapters/terminal/cli.ts`    | Выбор интерактивного TUI или построчного управления генерацией                             |
| `adapters/terminal/mouse.ts`  | Разбор событий мыши, отделение пакетов от клавиатуры и выбор видимой панели по координатам |
| `adapters/terminal/search.ts` | Буквальный Unicode-поиск, отображение совпадений на перенесённые строки и подсветка        |
| `adapters/terminal/scroll.ts` | Выбор панели, независимые позиции, границы прокрутки и слежение за концом потока           |
| `adapters/terminal/tui.ts`    | Экранированный ANSI-интерфейс, размеры окна, клавиши и восстановление терминала            |

`S` отменяет текущую генерацию. `q` и Ctrl+C передают сигнал обработчику приложения;
TUI восстанавливает режим терминала и освобождает запущенное им чтение stdin.
Единый обработчик SIGINT/SIGTERM отменяет генерацию, фоновые задачи и потоки
Ollama, останавливает адаптеры и ожидает их отключения. После очистки процесс
завершается явно, даже если библиотека оставила открытые дескрипторы. Если
отключение зависло, выход происходит не позднее чем через две секунды. Ошибка
старта использует тот же путь с кодом 1; повторные сигналы не запускают очистку заново.

## Музыка

Музыкальные команды обходят модель и очередь генерации. Они сериализуются отдельно
для каждого Discord-сервера. На сервер приходится один плеер и одно голосовое
подключение; разные серверы могут воспроизводить музыку одновременно.

| Модуль                            | Ответственность                                                                    |
| --------------------------------- | ---------------------------------------------------------------------------------- |
| `adapters/discord/music/index.ts` | Сборка общего runtime, обработчика команд и интерактивного управления музыкой      |
| `adapters/music/process.ts`       | Процессы Bun, ограниченный сбор метаданных и поток `yt-dlp` → FFmpeg               |
| `adapters/music/library.ts`       | Проверка и атомарное хранение именованных плейлистов, миграция старых списков      |
| `core/music/queue.ts`             | Выбор следующего трека, повтор, перемешивание и исключение неудачных источников    |
| `core/music/status.ts`            | Копируемые снимки состояния и подписка TUI с немедленной выдачей последнего снимка |

Плейлисты сервера хранятся в `memory/music_<guildId>.json` в формате
`{ version: 2, activeId, playlists: [{ id, name, tracks }] }`.
Предел — 25 плейлистов по 100 треков, имена длиной 1–60 символов уникальны
без учёта регистра. Чтение и запись используют Bun; временный файл заменяет
назначение через атомарный `rename`. Состояние в памяти меняется только после
успешной записи. Старый JSON-массив URL мигрирует в «Основной» при первом чтении;
невалидные файлы и неизвестные версии не перезаписываются.
Номера треков относятся к активному плейлисту. Текущая очередь — отдельная копия
выбранных для запуска треков. При смене активного плейлиста (включая удаление активного)
текущий трек доигрывает, а оставшаяся очередь и набор для повтора заменяются выбранным
плейлистом. Одноразовый переход обходит повтор текущего трека; shuffle сохраняется.
Меню треков и результаты поиска привязаны к ID исходного плейлиста.
Модуль `adapters/discord/music/commands.ts` распознаёт `!music` / `!музыка`, нормализует
русские алиасы команд, действий плейлиста и значений режимов. Аргументы с названиями,
ссылками и поисковым текстом не меняются. Discord использует общий распознаватель
для немедленной обработки команд и блокировки во время TTS независимо от языка.
Модуль `adapters/discord/music/messages.ts` добавляет к каждому музыкальному ответу
одну кнопку удаления, сохраняя лимит пяти рядов компонентов Discord.
Обработчик подтверждает нажатие через `deferUpdate` и удаляет исходный ответ
через `deleteReply`, что работает и для приватных сообщений. При удалении панели
снимаются её регистрация и таймер обновления; очередь и голосовое подключение не меняются.
Меню управления и формы редактирования используют ID целевого плейлиста независимо
от активного выбора. Добавление URL и разворачивание YouTube-плейлиста проверяют
оставшуюся ёмкость целевого списка. Создание и импорт копии не меняют `activeId`;
переключение происходит явно через `use` или кнопку «Сделать активным».
Единственный выпадающий список открывает управление выбранным плейлистом,
сохраняя активный выбор до нажатия этой кнопки.
Поиск из управления сохраняет ID целевого плейлиста в результатах; выбор найденного
трека проверяет существование этого плейлиста, а не совпадение с активным.
Префиксы `yt:`/`sc:` запускают поисковые экстракторы yt-dlp. Для `bc:`/`am:`/`ym:`
модуль `adapters/music/index-search.ts` использует существующий DuckDuckGo-клиент
с ограничением домена. Результаты повторно проверяются по хосту и пути отдельного
трека; максимум пять ссылок, без повторов и параметров отслеживания. HTTP-транспорт
ограничивает ответ 2 МБ, проверяет публичные IP и поддерживает отмену; общий срок
индексного поиска — 15 секунд. Ошибки индекса не вызывают поиск в другом сервисе.
Для обычного поиска сохраняется защита от изменения активного плейлиста.
Приватные компонентные взаимодействия и формы из приватного сообщения используют
`deferUpdate`/`editReply`: текущий экран заменяется с очисткой прежних вложений.
Переходы из общей панели создают приватный ответ. Кнопки возврата повторно строят
родительский экран; приватный плеер не регистрируется как общая панель сервера.
Запрос удаления хранит ID, снимок плейлиста, автора, сервер и срок действия
пять минут. Подтверждение одноразовое; повторная проверка прав и снимка выполняется
в общей очереди команд сервера перед атомарным сохранением. Последний плейлист
удалить нельзя; при удалении активного выбирается первый оставшийся.

Переносимый файл плейлиста имеет формат
`{ format: "relaksacher-playlist", version: 1, name, tracks }`.
Модуль `adapters/music/transfer.ts` проверяет формат целиком и скачивает вложение
только с HTTPS-хостов Discord CDN, без редиректов, с лимитом 128 КиБ по фактически
прочитанным байтам и сроком 15 секунд. Завершение приложения отменяет скачивание.
Экспорт не включает внутренние ID и состояние сервера; импорт создаёт новый ID,
проверяет уникальность имени и сохраняет новую библиотеку атомарно.

YouTube-плейлист разворачивается в URL отдельных видео, без загрузки аудио.
Импорт ограничен оставшейся ёмкостью, 45 секундами и 4 МБ вывода. Приватные или
некорректные записи пропускаются; неудачный импорт не перезаписывает плейлист.

Для каждого текущего трека `Bun.spawn` запускает `yt-dlp` и FFmpeg. Между ними
передаётся Web Stream, а PCM-поток адаптируется к Node readable только на границе
`@discordjs/voice`. Stop, skip, выход из войсчата и завершение приложения
останавливают оба процесса. Если звук не начал играть за 45 секунд, трек пропускается.

Повтор трека действует только при естественном завершении: skip всё равно
переключает трек. Повтор очереди использует исходный набор текущего запуска.
Неудачные источники исключаются до следующего `play`. Перемешивание сохраняет
дубликаты и не меняет файл плейлиста. Режимы сохраняются между stop/play в текущем
процессе; после перезапуска выключены. Через 60 секунд после опустошения очереди
бот покидает канал.

Поиск использует `ytsearch5:` и `scsearch5:` через тот же ограниченный запуск
метаданных с отменой при завершении приложения. Результаты проверяются через
список разрешённых хостов. Списки выбора ссылаются на случайные токены,
привязанные к автору и серверу на пять минут; хранилище ограничено 100 поисковыми списками.
Выбор снова проходит общую проверку голосового канала и лимита плейлиста.
Выбор запуска из плейлиста привязан к снимку списка, автору и серверу;
проверка снимка выполняется внутри очереди команд. Перезапуск подавляет
автоматический переход Idle на время остановки старого ресурса. `startQueueAt`
выбирает суффикс плейлиста и ставит выбранный трек первым даже при shuffle.

Название и длительность текущего трека загружает `adapters/music/metadata.ts`
отдельным ограниченным запросом yt-dlp без скачивания аудио. Запрос отменяется
при смене трека, остановке и выходе; устаревшие ответы не изменяют панель.
Ошибка метаданных не останавливает воспроизведение.
Плейлист и очередь читают снимок списка вне очереди управляющих команд:
загрузка названий не блокирует stop/skip. На список приходится до трёх параллельных
запросов; одинаковые URL объединяются. Кэш ограничен 500 URL: успешные результаты
хранятся час, ошибки — минуту. Ответ делится на страницы до 1900 символов. Названия экранируются
для Markdown, длительность выводится как m:ss или h:mm:ss.

## Выбор API

Используйте Bun API для файлов, процессов и настроек, Web API для HTTP, потоков и
отмены. Node-совместимость остаётся там, где она нужна: атомарный `rename`,
управление терминалом и граница голосовой библиотеки. Не заменяйте эти операции
дополнительными shell-процессами только ради удаления импорта `node:`.

TUI включает события кнопок и колёсика в режиме SGR (1000/1006), с разбором
legacy X10 для совместимых терминалов. [Формат событий описан в спецификации xterm](https://invisible-island.net/xterm/ctlseqs/ctlseqs.pdf).
Координаты вычисляются из того же layout, что рисует панели, и ограничены видимой
областью; resize пересчитывает границы. Неполные пакеты собираются между чтениями,
а данные мыши удаляются до декодера клавиш. Поток совместимости Node используется
только как вход `readline`. При закрытии обработчики и таймеры снимаются, а
терминалу отправляется отключение режима мыши до выхода из альтернативного экрана.

Поиск TUI ограничен текущей панелью. Запрос экранируется перед сопоставлением,
поэтому метасимволы не становятся регулярным выражением. Поиск выполняется до
мягкого переноса строк, а подсветка добавляется только к уже очищенному тексту.
Обычные обновления данных не перемещают окно к совпадению: переход выполняется
при изменении запроса или командах `n`/`N`. Новый запрос модели закрывает поиск
по ответу, мыслям или запросу предыдущей сессии.

## Подключение нового интерфейса

Ядро не импортирует Discord или конфигурацию окружения. Импорт модулей не запускает
клиентов. Чтобы добавить другой интерфейс, создайте помощника и вызовите:

```js
const session = assistant.createSession({
  conversation: [{ role: "user", content: "Привет!" }],
  context: { scopeId: "my-group", authorName: "Алиса" },
  think: false,
  platformInstructions: "Ты общаешься через терминал.",
  onUpdate: async ({ text, status, final }) => {
    // Здесь можно отобразить накопленный ответ и состояние инструмента.
    // Во время работы инструмента status содержит его вызов, иначе — пустую строку.
    console.log(text);
  },
});
await session.run();
// session.stop() отменяет активную генерацию или запрос в очереди.
```

Каждая сессия запускается один раз. В результате доступны `text`, `thinkingLog`,
`failed`, `stopped` и `timedOut`. Ядро ожидает завершения обработчика обновления,
поэтому адаптер может регулировать темп доставки. Рассуждения доступны только
локальному мониторингу и журналу. Интервал обновлений Discord — 1200 мс.

Идентификаторы областей памяти могут содержать латинские буквы, цифры, `_` и `-`.
Discord использует ID сервера и файлы `memory/<guildId>.json`. Чтобы отключить
постоянную память для диалога, не передавайте `scopeId`.

## Распознавание речи

`src/core/speech/transcription.ts` предоставляет общий клиент whisper.cpp и ограниченную
очередь с одним исполнителем. `index.ts` передаёт его обоим адаптерам.
`src/adapters/speech/voice.ts` скачивает аудио только с разрешённых HTTPS-хостов,
без перенаправлений, с ограничением размера и времени. Telegram разрешает file ID
через Bot API; Discord выбирает вложение сообщения с флагом IsVoiceMessage.
Адаптеры публикуют обычный текст ответом на исходник, минуя сессии Ollama.

`src/core/speech/whisper-server.ts` управляет локальным процессом whisper-server:
проверяет готовность перед подключением адаптеров, повторно использует работающий
сервер и завершает только собственный дочерний процесс при остановке приложения.

Вывод stdout/stderr дочернего Whisper читается через pipe и передаётся в console
с префиксом `[whisper]`, чтобы TUI показывал его в панели логов. Прямой вывод
дочернего процесса в терминал не используется; незавершённые строки ограничены.

`src/core/memory/transcript-history.ts` хранит до 1000 успешных расшифровок Discord
и идентификаторы отправленных частей. При чтении истории исходник заменяется
распознанным текстом от имени говорящего, части доставки исключаются. Если
исходник вне окна истории, одна расшифровка занимает место сообщения доставки.
Telegram сохраняет текст под идентификатором исходного сообщения в обычном
ограниченном кэше чата/темы. Эти кэши живут до перезапуска приложения.

## Синтез речи

`src/adapters/discord/tts.ts` обрабатывает команды TTS отдельно от Ollama,
сериализует запросы каждого сервера и отменяет их через AbortSignal. Silero
производит raw PCM, `createMusicPipeline` конвертирует его в PCM 48 кГц stereo.
Отдельный AudioPlayer временно заимствует подключение музыки, приостанавливая
и затем восстанавливая её плеер; собственное подключение закрывается после речи.
Discord-адаптер блокирует конфликтующие музыкальные команды и кнопки во время
озвучки. Завершение приложения отменяет очереди и дочерние процессы.

`src/adapters/speech/silero.ts` содержит выбор модели Silero по языку текста, запуск raw PCM → FFmpeg и очередь синтеза
голосовых файлов для Telegram и Discord. Для файлов PCM ограничен двумя минутами,
по его сэмплам рассчитываются длительность и waveform. Вторая конвертация
создаёт mono OGG/Opus 32 кбит/с. Discord отправляет единственное вложение с
IsVoiceMessage, duration и waveform; Telegram использует sendVoice и InputFile.
Обе команды перехватываются до сессии модели; shutdown отменяет синтез и очередь.

В Nix shell Whisper по умолчанию запускается ботом (`WHISPER_AUTO_START=true`),
Silero вызывается как CLI на запрос. Ollama работает независимо как системный
сервис NixOS с CUDA; системные требования описаны в README.

Общий `speechSource` выбирает одного случайного спикера на реплику (или явно заданного
через `--speaker`/настройки) и русскую или английскую
локальную модель и голос, передаёт текст аргументом без shell в `scripts/silero-tts.py`.
Скрипт использует CPU PyTorch, загружает модель на каждый запрос и синтезирует
фрагменты текста в 48 кГц mono s16le. Вывод модели направлен в stderr, stdout
содержит только PCM. Существующая отмена процесса и лимиты очередей действуют
на синтез Silero. Модели автоматически не скачиваются.

`adapters/discord/speech-text.ts` подставляет читаемые имена вместо упоминаний
пользователей перед Discord TTS и генерацией голосовых файлов. Используется
исходное сообщение, включая ответ, с приоритетом ника сервера над глобальным
именем и username. Повторяющиеся ID разрешаются один раз на реплику;
недоступные пользователи заменяются словом «пользователь».

## Объединение серий

`src/core/message-batches.ts` хранит ожидающую серию на канал/тему и объединяет
последовательные сообщения одного автора с debounce `MESSAGE_BATCH_WINDOW_MS`.
Новая команда, смена автора/адресата ответа и управляющие события закрывают серию.
Лимиты — 20 сообщений/10 секунд, кеш алиасов — 1000 ID. Явные ответы расширяются
только через этот локальный кеш, без чтения соседей из API. Ответы бота сохраняются
как группы фрагментов. Shutdown отбрасывает ожидающие серии и завершает ожидателей.
Discord использует представление первого сообщения с объединёнными текстом,
вложениями и упоминаниями; методы доставки привязаны к первому оригиналу.
Telegram сохраняет смещения entities и изображения всех частей отдельно от
единственного поля photo. Голосовые вложения для транскрипции обрабатываются сразу.

## Разделение музыкального адаптера

`adapters/discord/music/index.ts` связывает команды и взаимодействия с состоянием серверов,
хранилищем плейлистов и голосовым воспроизведением. Самостоятельные части вынесены:

- `adapters/music/url.ts` проверяет ссылки и нормализует YouTube-плейлисты.
- `adapters/music/youtube-playlist.ts` получает ограниченный список треков через yt-dlp.
- `adapters/music/search.ts` выполняет поиск по провайдерам.
- `adapters/discord/music/track-list.ts` кеширует метаданные и формирует страницы списков с выбором трека.
- `adapters/discord/music/panel.ts` строит панель по снимку состояния плеера.
- `adapters/discord/music/help.ts` хранит текст справки.

Прежние экспорты поиска и загрузки плейлистов из `adapters/discord/music/index.ts` сохранены.
`adapters/discord/message.ts` содержит разбиение сообщений, подписи инструментов
и выбор вложений; жизненный цикл Discord-клиента остаётся в `adapters/discord/index.ts`.

## Доступ Discord по ролям и пользователям

`adapters/discord/access/store.ts` проверяет формат правил, вычисляет совпадения
ролей/участников и сохраняет файлы `access_<guildId>.json` в каталоге памяти.
Записи одного сервера сериализованы, файл заменяется атомарно; состояние в памяти
меняется только после успешной записи. Отсутствие файла разрешает все функции,
ошибка чтения или проверки прав не открывает доступ.

`adapters/discord/access/index.ts` обрабатывает администраторские команды `!access` /
`!доступ`, проверяет существование ролей и участников сервера и выдаёт отказ.
Текстовая команда публикует только кнопку открытия, привязанную к автору и серверу.
Нажатие подтверждается приватно через `MessageFlags.Ephemeral`; после проверки
автора сообщение открытия удаляется, а запрос становится одноразовым.
`adapters/discord/access/menu.ts` управляет приватным меню функций, режимов,
ролей и пользователей. Изменения хранятся в черновике до «Сохранить»;
переход назад и закрытие отбрасывают черновик. Каждое действие повторно проверяет
автора, сервер и право Administrator. Сессии ограничены по числу и времени,
параллельные действия одной сессии не меняют черновик одновременно.
Личные сообщения и slash-команды для настроек не используются.
`adapters/discord/index.ts` применяет проверки до генерации, чтения источника озвучки,
отмены ожидающей серии TTS и обработки музыкальных взаимодействий. Запрещённые
запросы модели также не попадают в наблюдение и выбор самостоятельных реплик.
Ограничение `music` применяется к кнопкам, меню и формам; удаление собственного
сообщения панели остаётся доступно. Администраторы обходят списки доступа,
но не обычные требования голосового канала. Остановка генерации сохраняет
проверки автора запроса и модератора, чтобы можно было завершить уже начатую работу.

## Границы модулей и размер файлов

TypeScript-файлы исходников, тестов и инструментов ограничены 600 физическими
строками. `scripts/check-file-size.ts` выполняет проверку через `bun run check:size`
перед линтером. Публичная фабрика музыки сохраняет прежние экспорты:

- `adapters/discord/music/index.ts` собирает подсистему без запуска сетевых подключений.
- `adapters/discord/music/runtime.ts` владеет состоянием серверов, воспроизведением,
  телеметрией, отменой и завершением дочерних процессов.
- `adapters/discord/music/command-handler.ts` сериализует команды сервера и управляет очередью.
- `adapters/discord/music/playlist-commands.ts` выполняет изменения именованных плейлистов и импорт.
- `adapters/discord/music/library-view.ts` строит меню библиотеки и экспортирует плейлисты.
- `adapters/discord/music/interactions.ts` проверяет формы, кнопки и выбор треков, передавая
  изменения общему обработчику команд.
- `adapters/discord/music/request.ts` описывает единый контракт сообщений и взаимодействий.

`adapters/discord/delivery.ts` синхронизирует поток ответа с сообщениями Discord,
кнопками остановки и доставкой ответов только с медиа. `adapters/discord/message.ts`
содержит также представление автора и название ветки. `adapters/telegram/message.ts`
собирает серии сообщений, сохраняет привязку изображений к копиям сообщений,
форматирует автора и разбивает текст. Жизненный цикл клиентов остаётся в адаптерах.

Тесты жизненного цикла помощника, истории Discord и транспорта Telegram отделены
от остальных сценариев. `test/support/assistant-fixture.ts` и `test/support/telegram-fixture.ts`
создают независимые зависимости для каждого теста и не регистрируют проверки.

`adapters/discord/controls.ts` задаёт единый вид общих кнопок меню: ❌ для закрытия
и «←» для возврата. Настройки доступа и музыкальные меню используют эти
фабрики; проверка автора и обработка действия остаются в соответствующих модулях.

### Статистика процесса

`core/statistics.ts` хранит общий и пофункциональные счётчики в постоянном хосте
`index.ts`, выдавая изолированные снимки с монотонным аптаймом. Хост передаёт
`record` в каждый экземпляр `runtime/application.ts`, а read-only источник — через
CLI в TUI; замена runtime не обнуляет статистику. Адаптеры отмечают создание сессии
модели, команды и действия меню на границах маршрутизации. Распознавание команд
для статистики находится в `adapters/shared/request-statistics.ts`, немедленные
броски учитываются в `adapters/shared/dice.ts`. `adapters/terminal/statistics.ts`
форматирует аптайм и счётчики; TUI перерисовывает их при изменении суммы или секунды
аптайма и отключает таймер при закрытии.

### Журнал входящих запросов

`core/request-log.ts` последовательно дописывает JSONL в `REQUEST_LOG_FILE`
(по умолчанию `logs/requests.jsonl`). Экземпляр принадлежит постоянному хосту;
один callback передаёт события в статистику и файловый журнал, поэтому мягкий
рестарт не создаёт конкурирующих писателей. При завершении хост останавливает
приложение, затем закрывает журнал с ожиданием накопленных записей.

`adapters/shared/request-context.ts` добавляет к событию только входной текст,
идентификаторы пользователя, сервера/чата и канала/темы. Ответы на сообщения,
история и содержимое сообщения под кнопками не читаются. Для `transcribe` текст
отбрасывается и в адаптере, и в писателе. Обработчик кубов передаёт третьим
аргументом callback точный результат единственного вычисления; писатель сохраняет
его в `result` исключительно для функции `roll`, до доставки сообщения. Писатель явно перечисляет поля JSON,
чтобы случайные дополнительные поля контекста не сохраняли ответы или мысли.
Для атомарного добавления в существующий файл используется Node `appendFile`:
у Bun нет отдельного append-to-path API. Очередь сохраняет порядок записей,
ошибки записи сообщаются через console и не блокируют следующие запросы.

### Обновление терминального интерфейса

`runtime/application.ts` экспортирует фабрику CLI/TUI и фабрику состояния
операторской сессии. Загрузчик включает весь граф терминальных модулей в новую
сборку до остановки текущего runtime, поэтому синтаксическая ошибка в TUI
не отключает работающий интерфейс. Хост после замены ассистента закрывает старый
интерфейс и вызывает новую фабрику, повторно передавая мост ассистента, статистику,
музыкальный монитор и `TerminalSession` с логами, навигацией и поиском.
`close()` построчного CLI дожидается освобождения reader stdin. Если новая фабрика
падает, хост повторно открывает предыдущий интерфейс и выводит ошибку.
Сам хост и загрузчик по-прежнему обновляются только полным запуском процесса.

### Журнал инструментов модели

Сессионный callback `onToolCall` вызывается в цикле исполнения ассистента один раз
до каждого инструмента, включая `enable_thinking`. Адаптеры через `toolRecorder`
связывают вызов с исходным пользователем, сервером/чатом и ID запроса. Callback
телеметрии получает `RequestDetails` с `kind: "tool"`; хост направляет его только
в журнал, не увеличивая счётчики пользовательских запросов. Писатель сохраняет
`event: "tool_call"` и только имя/аргументы функции, исключая результаты,
историю и текст ответа. Ошибка callback не прерывает исполнение инструмента.
Результаты кубов передаются тем же каналом с `kind: "roll"` и полем `result`.
